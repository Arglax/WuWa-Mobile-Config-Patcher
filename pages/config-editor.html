Engine CVar Section Guards & Canonical Rules

CVarSectionGuard.kt Mechanics

Unreal Engine 4 & 5 strictly parse configuration variables based on INI section headers. A CVar placed in the wrong section can be silently discarded by the game engine. Under Characteristics and Behavior, you can see how the app behaves or enforces the code.

VIBRANT RED WARNING (#FF2222)
Any CVar placed under an illegal header is highlighted in bold vibrant red. When you tap Save, the app prompts you with Auto-Fix Sections to cleanly migrate misplaced lines into their canonical headers.
INI Section Header Valid CVar Prefix / Rules Whitelisted / Strict Behavior
[/Script/Engine.RendererSettings] All r. variables (except r.SupportAllShaderPermutations) Canonical rendering section
[/Script/Engine.RendererOverrideSettings] r.SupportAllShaderPermutations, r., or dp. Strictly Whitelisted: Never moved or altered during Auto-Fix
[/Script/Engine.StreamingSettings] All s. variables (Texture & Asset Streaming) Auto-fixed from [SystemSettings] if present
[/Script/Engine.GarbageCollectionSettings] All gc. variables (Memory & GC frequency) Canonical GC section
[/Script/Engine.NetworkSettings] n.VerifyPeer, p.EnableMultiplayerWorldOriginRebasing Network & Multiplayer parameters
[/Script/UnrealEd.CookerSettings] All cook. directives Cooker & Package rules
[SystemSettings] / [ConsoleVariables] Universal root containers Accepts ANY valid CVar variable
[Core.Paths] & [Core.System] Engine core directory paths Strictly Whitelisted: Never touched or altered
DEVICEPROFILES.INI SYNTAX RULE
Inside DeviceProfiles.ini, CVars must be structured as CVars=Key=Value. The patcher enforces this formatting automatically while protecting profile pointers like BaseProfileName and DeviceScore.
